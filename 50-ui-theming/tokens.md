# 设计令牌

只做浅色，没有深色分支——owner 明确要求，不是漏做。下面每个取值都带理由，
不是照抄一份配色表。取值全部来自
[`theme/theme-acme.css`](theme/theme-acme.css)，可以直接对照源文件核对。

## 字体

| 用途 | 栈 | 理由 |
|---|---|---|
| 正文（拉丁） | `Inter`（400/500/600） | 现代界面字体的默认选择，三档字重覆盖正文/中等强调/标题 |
| 正文（CJK 回退） | `"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC"` | **Inter 不含汉字字形**。不补这串，中文会直接跌到浏览器默认 sans-serif，跟 Inter 的字重/字怀完全不搭 |
| 等宽 | `ui-monospace, SFMono-Regular, "SF Mono", Menlo, Monaco, Consolas, ...` | 用于文件路径、commit hash、分支名、日志、diff。**这条没有覆盖**——Forgejo 自己的 `--fonts-monospace` 默认值已经是 `ui-monospace` 栈，没有理由重新定义一遍 |

完整覆盖值（`--fonts-override`，接进 Forgejo 官方留的钩子
`--fonts-regular: var(--fonts-override, var(--fonts-proportional))`）：

```css
--fonts-override: Inter, -apple-system, "Segoe UI", system-ui, "PingFang SC",
                  "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", "Noto Sans", Roboto;
```

## 字号阶

**固定 rem 阶，不做流体排版**——这是产品向的管理界面，不是营销页，字号不需要
随视口连续缩放，固定阶梯反而让"标题=19px"这种视觉锚点在任何窗口宽度下都一样，
方便截图对照和评审。

rem 锚在 Forgejo `base.css` 自己定的 **14px** 基准上（不是 16px 浏览器默认）——
沿用宿主应用已有的基准，不引入第二套换算。

| 层级 | rem | px（÷14 基准） | 字重 | 对应元素/用途 |
|---|---|---|---|---|
| h1 | `1.35714286rem` | 19 | 600 | 页面主标题 |
| h2 | `1.07142857rem` | 15 | 600 | 卡片/分区标题 |
| 正文 | `1rem` | 14 | 400 | 默认文本，不覆盖（沿用基准本身） |
| small | `.92857143rem` | 13 | 400/500 | 次要文本：`.time`/`.meta`/表单 label |
| micro | `.82142857rem` | 11.5 | 400/600 | commit sha、mini 标签、help 文字、file-info |

上游自己的 h1 默认是 `2rem`（28px）、h2 是 `1.71428571rem`（24px）——比这套
阶梯松得多。压缩到 19/15 是"密度是特性"这条原则的直接体现，不是为了省空间
而牺牲可读性：管理界面里标题不需要跟营销页一样抢注意力。

## 行高

| 场景 | 值 | 理由 |
|---|---|---|
| 正文 | `1.45` | 常规阅读行高，不特别宽松也不挤 |
| 日志 / 代码 | `1.7` | 等宽字体在高密度场景（diff、日志滚动）需要更松的行高，否则连续的竖线字符（`|`、`│`）会糊成一条 |

## 圆角

```css
--border-radius: 8px;
--border-radius-medium: 12px;
```

上游默认是 4px / 6px。放大到 8/12 是刻意的——配合下面"密度是特性"的间距收紧，
更大的圆角在视觉上抵消"信息更密"带来的局促感，两者是配套决策，不是分别调的。

## 间距节奏

| 项 | 值 | 说明 |
|---|---|---|
| 卡片内边距 | 16–18px | 卡片类容器（`.ui.attached.segment` 等）统一在此区间，不做逐组件特调 |
| 分区节奏 | 14–22px | 相邻分区/字段之间的垂直间距 |
| 描边 | 0.5–1px | 卡片边框、分隔线；细描边配合浅色背景，避免比正文更抢眼 |

**密度是特性**：默认 Fomantic 的留白是给通用场景准备的，内部工具的使用者是
每天盯着这个界面的人，不是偶尔路过的访客——单位屏幕信息量优先于呼吸感。

## 配色

### 强调色

```css
--color-primary: #454b8c;   /* 低饱和深靛蓝 */
```

**第一版用的是 `#4338CA`，被否**——铺满按钮之后太冲，跟"内部工具"的定位不
符。教训：**强调色只用于主按钮、当前 tab 指示器、链接、聚焦环、选中态**，
不铺大面积背景。`#454b8c` 饱和度更低、更沉，同样的用法下不会抢戏。

上游品牌色是 `--color-primary: #c2410c`（橙），本次改造把这条变量及其
`dark-1..7` / `light-1..7` / `alpha-10..90` 整条色阶一起换掉，不是只改基准色
再让派生值算出来偏色。

### 中性色（zinc 阶）

上游 `--zinc-*` 阶偏暖，这里换成**冷中性**（略带蓝底）——原因见
[theming-guide.md 第二节](theming-guide.md#二优先改变量其次才是选择器)：
改这一处底层色阶，47 个语义变量跟着一致地变，不会出现深浅不一致。

| 变量 | 取值 | 变量 | 取值 |
|---|---|---|---|
| `--zinc-50` | `#fafafb` | `--zinc-500` | `#6e7488` |
| `--zinc-100` | `#f5f6f8` | `--zinc-550` | `#5f6578` |
| `--zinc-150` | `#edeef1` | `--zinc-600` | `#515669` |
| `--zinc-200` | `#e3e5ea` | `--zinc-650` | `#464b5b` |
| `--zinc-250` | `#dadce3` | `--zinc-700` | `#3d4150` |
| `--zinc-300` | `#cfd2da` | `--zinc-750` | `#32353f` |
| `--zinc-350` | `#b7bbc6` | `--zinc-800` | `#272a32` |

| `--zinc-450` | `#868c9c` | `--zinc-900` | `#17191f` |

18 档，从 `theme-acme.css` 逐条取值，没有手改或四舍五入。

### 语义色

只在 CI 状态、告警、diff 里出现——不用作装饰色，也不用在跟"状态"无关的地方：

| 语义 | 取值 |
|---|---|
| 成功 / 绿 | `#0f7b4f` |
| 失败 / 红 | `#b42318` |
| 警告 / 琥珀 | `#b45309` |
| 信息 / 蓝 | `#1d4ed8` |
